# AECored_1.2

Ядро системы учета энергии ActiV-Energy.

Рабочая заготовка ядра построена как модульное приложение Python 3.7+ для Debian Linux и устанавливается как отдельный systemd-сервис для каждого `user_id`.

## Текущая структура

```text
AECored_1.2/
├── aecored/
│   ├── __init__.py
│   ├── aecored.py             # Главный модуль и точка входа
│   ├── config.py              # Загрузка и проверка конфигурации
│   ├── module.py              # Базовый интерфейс модулей
│   ├── lifecycle.py           # Жизненный цикл модулей
│   ├── core_module.py         # Минимальный внутренний модуль ядра
│   ├── systemd_watchdog.py    # Интеграция с watchdog systemd
│   └── process_name.py        # Установка имени процесса Linux
├── install.py                 # Установка, обновление и удаление экземпляра
├── config.ini                 # Шаблон конфигурации
└── .gitignore
```

## Конфигурация

Пока используется только идентификатор пользователя:

```ini
[aecored]
user_id = 10
```

Значение `10` является временным. Установщик при создании экземпляра записывает сюда реальный ID пользователя.

## Установка как systemd-сервиса

Установщик работает от `root` и проверяет Python 3.7+ и наличие `venv`.

Из каталога репозитория:

```bash
python3 install.py install 10
```

Будет создан экземпляр:

```text
/opt/actv-energy/aecored/10/
├── aecored/
├── config.ini
└── .venv/
```

и systemd-сервис:

```text
10_AECored.service
```

Сервис включается в автозапуск и сразу запускается.

Проверка:

```bash
systemctl status 10_AECored.service
journalctl -u 10_AECored.service -f
```

## Обновление

Обновление специально выполняется как полная замена кода экземпляра:

1. остановить systemd-сервис;
2. отключить старый экземпляр;
3. сохранить `config.ini`;
4. удалить старый каталог с кодом и виртуальным окружением;
5. загрузить свежий `main` из GitHub;
6. установить свежий код;
7. заново создать `.venv`;
8. заново создать systemd unit;
9. выполнить `daemon-reload`;
10. включить и запустить сервис.

Команда:

```bash
python3 install.py update 10
```

Конфигурация экземпляра при обновлении сохраняется.

## Удаление

Полное удаление экземпляра:

```bash
python3 install.py remove 10
```

Удаляются systemd unit, код экземпляра и виртуальное окружение.

## Ручной запуск

Для отладки ядро можно запускать непосредственно из исходного дерева:

```bash
python3 -m aecored.aecored config.ini
```

При запуске через systemd используется тот же `aecored.aecored`, но systemd получает `READY=1` и контролирует heartbeat через watchdog.

## Архитектурный принцип

`aecored.py` является главным модулем и отвечает за жизненный цикл самого AECored, а функциональные подсистемы подключаются как отдельные модули. Каждый модуль имеет этапы `initialize()`, `start()`, `stop()` и `shutdown()`.

Каждый экземпляр пользователя является отдельным systemd-сервисом вида `ID_AECored.service`. В дальнейшем в этот каркас будут добавляться планировщик, запуск внешних процессов/драйверов, IPC/API, RabbitMQ/MQTT, MariaDB и административное управление.
